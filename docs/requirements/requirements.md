# SNSプラットフォーム要件定義書

**バージョン**: 1.0
**作成日**: 2026-03-24
**ステータス**: Draft

---

## 1. システム概要

### 1.1 目的
従来のSNSが抱える「瞬間的で忘れ去られるコンテンツ」の課題を解決し、長期的な思考と作品性を持つアウトプットを促進するプラットフォームを構築する。

### 1.2 コアバリュー
- **不可逆性**: 全ての変更履歴を永続的に記録し、改ざん・削除を不可能にする
- **学術性**: 論文のような引用システムで知識の系譜を可視化
- **品質保証**: AI査読により一定の品質を担保

### 1.3 対象ユーザー
- 思想家、研究者、クリエイター
- 長期的な影響を持つコンテンツを発信したい個人
- 知的な議論と深い思考を求めるコミュニティ

## 2. 機能要件

### 2.1 アカウント管理

#### 2.1.1 ユーザー登録
- **FR-001**: メールアドレスまたはソーシャルログインによる登録
- **FR-002**: 年齢確認（18歳以上/未満の判定）
- **FR-003**: プロフィール情報の設定（名前、bio、専門分野など）
- **FR-004**: 退会機能（ただしコンテンツは永久保存）

#### 2.1.2 退会後の扱い
- **FR-005**: 退会後もコンテンツは完全保存
- **FR-006**: 退会ユーザーのプロフィールは「[退会済みユーザー]」として表示
- **FR-007**: GDPR対応として、退会時に「匿名化」オプションを提供（著者情報のみ削除、コンテンツは保持）

### 2.2 投稿機能（Output）

#### 2.2.1 基本投稿
- **FR-010**: Markdown形式でのテキスト投稿（最大文字数: 50,000文字）
- **FR-011**: 画像添付（最大5枚、各10MB）
- **FR-012**: タグ設定（最大10個）
- **FR-013**: 分野カテゴリ選択（科学/芸術/哲学/技術/社会/その他）

#### 2.2.2 編集と履歴
- **FR-014**: 投稿後の編集機能
- **FR-015**: 編集履歴の自動記録（誰が・いつ・何を変更したか）
- **FR-016**: 任意のバージョンへの閲覧機能（diff表示）
- **FR-017**: 編集は削除不可（履歴の改ざん防止）

#### 2.2.3 一意ID
- **FR-018**: 全ての投稿にシステム生成の一意ID（例: `OUT-2026-0324-A1B2C3`）
- **FR-019**: IDはユーザー側で制御不可
- **FR-020**: IDは投稿ページURLに含まれる

### 2.3 引用システム

#### 2.3.1 引用作成
- **FR-030**: 他の投稿をIDで引用する機能
- **FR-031**: 引用箇所の明示（引用元のテキスト抜粋を表示）
- **FR-032**: 引用タイプの指定（同意/批判/発展/参照）
- **FR-033**: 1投稿あたり最大50件の引用可能

#### 2.3.2 被引用追跡
- **FR-034**: 自分の投稿を引用している投稿の一覧表示
- **FR-035**: 引用関係のグラフ可視化（知識の系譜）
- **FR-036**: 被引用数のカウント表示

#### 2.3.3 「同意見」機能
- **FR-037**: 類似投稿に対する「同意見」ボタン
- **FR-038**: 同意見数の表示
- **FR-039**: 同意見を示したユーザーの一覧

### 2.4 AI査読システム（Phase 1: MVP）

#### 2.4.1 コンテンツモデレーション
- **FR-040**: 投稿時のAI自動査読（非同期処理）
- **FR-041**: 暴力的・性的・差別的コンテンツの検出
- **FR-042**: 問題コンテンツの自動除外またはマイルド化提案
- **FR-043**: AI査読結果の通知（承認/修正要求/却下）

#### 2.4.2 新規性判定（Phase 2）
- **FR-044**: 既存の全投稿との類似度計算
- **FR-045**: 新規性スコア（0-100%）の算出
- **FR-046**: 閾値（例: 70%）以上でPublic、未満でPrivate判定
- **FR-047**: 類似投稿の提示（「この投稿と類似しています」）

#### 2.4.3 異議申立て
- **FR-048**: Private判定への異議申立て機能
- **FR-049**: コミュニティレビュー（Phase 2）

### 2.5 Public/Private Output

#### 2.5.1 Public Output
- **FR-050**: AI査読を通過し新規性が認められた投稿
- **FR-051**: 全ユーザーに公開
- **FR-052**: 検索・発見対象
- **FR-053**: 引用可能

#### 2.5.2 Private Output
- **FR-054**: 新規性なしと判定された投稿
- **FR-055**: フォロワーのみに公開
- **FR-056**: 検索対象外
- **FR-057**: Private投稿からの引用は不可

### 2.6 フォロー/フィード

#### 2.6.1 フォローシステム
- **FR-060**: ユーザーのフォロー/フォロー解除
- **FR-061**: フォロワー/フォロー中リストの表示
- **FR-062**: フォロー通知（オプション）

#### 2.6.2 フィード
- **FR-063**: 時系列フィード（フォロー中ユーザーの投稿）
- **FR-064**: サジェストフィード（引用数・評価ベース）
- **FR-065**: 分野別フィード（カテゴリフィルタ）

### 2.7 検索・発見

#### 2.7.1 検索
- **FR-070**: 全文検索（Public Outputのみ）
- **FR-071**: タグ検索
- **FR-072**: ユーザー検索
- **FR-073**: 高度な検索（期間・分野・引用数でフィルタ）

#### 2.7.2 ランキング
- **FR-074**: 引用数ランキング（デイリー/ウィークリー/月間/年間）
- **FR-075**: 新規性スコアランキング
- **FR-076**: 分野別ランキング

## 3. 非機能要件

### 3.1 不可逆性・セキュリティ

#### 3.1.1 ハッシュチェーン
- **NFR-001**: 全投稿・編集をSHA-256でハッシュ化
- **NFR-002**: 各レコードに親ハッシュを含める（Merkle Tree構造）
- **NFR-003**: ハッシュ不整合の検出機能

#### 3.1.2 外部アンカリング
- **NFR-004**: 1日1回、ルートハッシュをBitcoin/Ethereumに記録
- **NFR-005**: OpenTimestampsへの補助アンカリング
- **NFR-006**: アンカリング履歴の公開

#### 3.1.3 データ永続化
- **NFR-007**: 削除操作の禁止（論理削除も不可）
- **NFR-008**: バックアップの多重化（最低3箇所）
- **NFR-009**: 定期的な整合性チェック（週次）

### 3.2 パフォーマンス

- **NFR-010**: ページ読み込み時間: 2秒以内（90パーセンタイル）
- **NFR-011**: AI査読処理時間: 平均30秒以内
- **NFR-012**: 同時アクセス: 1,000ユーザー対応
- **NFR-013**: 引用グラフ生成: 5秒以内（100ノードまで）

### 3.3 スケーラビリティ

- **NFR-014**: 投稿数: 1,000万件まで対応
- **NFR-015**: ユーザー数: 100万人まで対応
- **NFR-016**: ストレージ: 水平スケール可能な設計
- **NFR-017**: データベース: 読み取りレプリカ対応

### 3.4 可用性

- **NFR-018**: システム稼働率: 99.5%以上
- **NFR-019**: 計画停止: 月1回以内、1時間以内
- **NFR-020**: 障害復旧時間（RTO）: 4時間以内
- **NFR-021**: データ損失許容時間（RPO）: 1時間以内

### 3.5 保守性

- **NFR-022**: コードカバレッジ: 80%以上
- **NFR-023**: APIドキュメント自動生成
- **NFR-024**: ログ保存期間: 1年
- **NFR-025**: モニタリング: エラー率/レスポンスタイム/リソース使用率

## 4. データモデル

### 4.1 主要エンティティ

#### User（ユーザー）
```
- id: UUID (PK)
- email: string (unique)
- username: string (unique)
- display_name: string
- bio: text
- age_verified: boolean
- is_active: boolean
- created_at: timestamp
- deleted_at: timestamp (論理削除用、匿名化時のみ使用)
```

#### Output（投稿）
```
- id: string (PK, 例: OUT-2026-0324-A1B2C3)
- user_id: UUID (FK)
- content: text
- category: enum
- tags: array[string]
- visibility: enum (public/private)
- novelty_score: float (0-100)
- ai_review_status: enum (pending/approved/rejected)
- hash: string (SHA-256)
- parent_hash: string (前バージョンのハッシュ)
- created_at: timestamp
- version: integer
```

#### OutputHistory（編集履歴）
```
- id: UUID (PK)
- output_id: string (FK)
- version: integer
- content: text
- edited_by: UUID (FK to User)
- hash: string
- parent_hash: string
- created_at: timestamp
```

#### Citation（引用）
```
- id: UUID (PK)
- source_output_id: string (FK, 引用元)
- target_output_id: string (FK, 引用先)
- citation_type: enum (agree/criticize/develop/reference)
- excerpt: text (引用箇所)
- created_at: timestamp
```

#### Agreement（同意見）
```
- id: UUID (PK)
- user_id: UUID (FK)
- output_id: string (FK)
- created_at: timestamp
- unique(user_id, output_id)
```

#### HashAnchor（外部アンカリング）
```
- id: UUID (PK)
- root_hash: string
- blockchain: enum (bitcoin/ethereum/opentimestamps)
- transaction_id: string
- anchored_at: timestamp
```

### 4.2 インデックス設計

- User: email, username
- Output: user_id, visibility, category, created_at, novelty_score
- Citation: source_output_id, target_output_id
- Agreement: output_id, created_at
- Full-text search: Output.content (Elasticsearch/PostgreSQL FTS)

## 5. ユーザーストーリー

### 5.1 投稿と履歴管理

**US-001**: 新規投稿
As a ユーザー
I want to Markdown形式で長文投稿を作成
So that 自分の思想を体系的に表現できる

**US-002**: 投稿の編集
As a ユーザー
I want to 過去の投稿を編集
So that 思想を深化させることができる

**US-003**: 履歴の閲覧
As a 閲覧者
I want to 投稿の編集履歴を時系列で見る
So that 著者の思考プロセスを理解できる

### 5.2 引用と知識の系譜

**US-004**: 他者投稿の引用
As a ユーザー
I want to 他のユーザーの投稿をIDで引用
So that 議論を発展させることができる

**US-005**: 被引用の確認
As a ユーザー
I want to 自分の投稿がどこで引用されているか見る
So that 自分の思想の影響を知ることができる

**US-006**: 知識の系譜可視化
As a 閲覧者
I want to 引用関係をグラフで見る
So that 思想の流れを視覚的に理解できる

### 5.3 発見とフィード

**US-007**: サジェストフィード
As a ユーザー
I want to 引用数の多い高評価な投稿を見る
So that 質の高いコンテンツに出会える

**US-008**: 分野別検索
As a ユーザー
I want to 自分の興味のある分野の投稿を探す
So that 関連する議論を見つけられる

### 5.4 AI査読

**US-009**: 新規性判定
As a ユーザー
I want to 投稿が既存コンテンツと類似していないか確認
So that オリジナリティを保証できる

**US-010**: 異議申立て
As a ユーザー
I want to Private判定に異議を申し立てる
So that 誤判定を修正できる

## 6. 制約事項

### 6.1 技術的制約
- データの物理削除は一切行わない
- 履歴の改ざん検出は必須
- AI査読の処理時間により投稿反映に遅延が発生

### 6.2 法的制約
- GDPR対応として匿名化機能を提供
- 違法コンテンツは法的要請に基づき閲覧制限可能
- 未成年者（18歳未満）の投稿は保護者同意が必要

### 6.3 ビジネス制約
- Phase 1は広告なしで運営（別途マネタイズ検討）
- 初期ユーザー数: 1,000人を想定
- 運用コスト: 月額50万円以内

## 7. インターフェース要件

### 7.1 Web UI
- レスポンシブデザイン（PC/タブレット/モバイル対応）
- Markdown編集エディタ（プレビュー機能付き）
- 引用グラフのインタラクティブ可視化（D3.js等）

### 7.2 API
- RESTful API（認証: JWT）
- GraphQL API（Phase 2）
- Webhook（引用通知など）

### 7.3 外部連携
- ソーシャルログイン（Google/Twitter/GitHub）
- OGPタグ対応（SNSシェア時のプレビュー）
- DOI連携（Phase 3）

## 8. 実装優先度

### Phase 1: MVP（3-6ヶ月）
- [P0] ユーザー登録・認証
- [P0] 基本投稿機能（作成・編集・履歴）
- [P0] ハッシュチェーン実装
- [P0] 引用システム（基本）
- [P0] AI査読（コンテンツモデレーションのみ）
- [P1] フォロー/フィード
- [P1] 全文検索

### Phase 2: 差別化（6-12ヶ月）
- [P1] 新規性判定AI
- [P1] Public/Private output分離
- [P1] 引用グラフ可視化
- [P2] 異議申立て・コミュニティレビュー
- [P2] 「同意見」機能

### Phase 3: エコシステム（12-18ヶ月）
- [P2] 外部アンカリング（Bitcoin/Ethereum）
- [P2] DOI付与
- [P3] DAO移行
- [P3] 分散ストレージ統合

## 9. 受入基準

### 9.1 機能テスト
- 全ての機能要件が実装され動作すること
- ユーザーストーリーが完遂できること

### 9.2 非機能テスト
- パフォーマンステスト: 全NFR基準をクリア
- セキュリティテスト: OWASP Top 10対策済み
- ハッシュ整合性テスト: 改ざん検出が動作

### 9.3 ユーザビリティテスト
- 5名の被験者がタスク完了率80%以上
- SUS（System Usability Scale）スコア70以上

## 10. リスク管理

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| GDPR違反訴訟 | 高 | 中 | 匿名化機能・法務レビュー |
| AI査読の誤判定 | 中 | 高 | 異議申立て機能・人間レビュー |
| ストレージコスト超過 | 中 | 中 | 段階的スケーリング・圧縮 |
| 初期ユーザー獲得失敗 | 高 | 中 | インフルエンサー招待・クローズドβ |
