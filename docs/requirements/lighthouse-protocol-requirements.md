## 1. プロトコルの核心思想

本プラットフォームは単なるSNSではなく、**「人類の知の地層」を形成するパブリック・アーカイブ**である。

### 1.1 基本原則（The Core Tenets）

1. **客観的評価の至上主義**
   - 投稿者の権威性を完全排除
   - 内容の論理整合性と希少性のみを評価

2. **無自覚な貢献の称揚**
   - ユーザーが価値を自覚していない投稿も、システムが客観的に評価し昇格

3. **改ざん不可能な履歴**
   - すべての投稿・修正・批判を永久保存
   - ユーザー退会後も知の系譜から消えない

4. **18歳以上の聖域**
   - 責任ある言論と論理整合性担保のための年齢制限

## 2. LLM査読システム（高度化）

### 2.1 コンセプト
LLMは「平均的な正解」を出す装置ではなく、**「平均からの乖離」を検知するセンサー**として機能する。

### 2.2 新規性判定の3つの軸

#### FR-LH-001: 乖離度（Divergence）
- **定義**: 既存のWebデータや標準的なAI回答から、意味ベクトルがどれだけ離れているか
- **実装**:
  - 投稿内容を埋め込みベクトル化
  - 既存投稿DB + 標準的なLLM生成文との距離を計算
  - 閾値以上の乖離を「新規性」として評価
- **優先度**: P0（Phase 2）

#### FR-LH-002: 内部密度（Density）
- **定義**: 乖離した「特異点」において、具体的かつ論理的な補強がどれだけ集中しているか
- **評価要素**:
  - 5W1Hの具体性
  - 一次情報（体験・観察・矛盾する感情）の有無
  - 微細な観察の密度
- **実装**: LLMプロンプトベースの密度スコア算出
- **優先度**: P0（Phase 2）

#### FR-LH-003: 逆シミュレーション
- **定義**: 別のLLMに続きを書かせ、AIが予測できない「人間固有の執着・跳躍」を検証
- **実装フロー**:
  1. 投稿の前半をLLMに入力し、続きを生成
  2. 実際の投稿後半との差異を計算
  3. 予測不能性が高いほど高評価
- **優先度**: P1（Phase 2）

#### FR-LH-004: AI生成物の許容
- **定義**: AIを用いた創作でも、独自性があれば正当にアーカイブ
- **実装**: AI生成フラグの任意開示（ペナルティなし）
- **優先度**: P2

## 3. ブラインド審査システム

### FR-LH-010: 著者情報の遮断
- **要件**: AI査読段階では投稿者の属性（フォロワー数、過去実績、プロフィール）を完全遮断
- **実装**:
  - 査読APIに投稿内容のみを渡す
  - user_id等のメタデータは査読後に結合
- **優先度**: P0（Phase 1）

### FR-LH-011: ブラインドフィード（オプション）
- **要件**: ユーザーが選択可能な「著者名非表示フィード」
- **実装**: フロントエンドで著者情報をマスキング
- **優先度**: P2（Phase 3）

## 4. 批判の価値化

### FR-LH-020: 共同貢献者（Contributor）記録
- **定義**: 正当な批判によって作品を磨いた者は「共同貢献者」として履歴に名を刻む
- **トリガー条件**:
  - `criticize`タイプの引用が作成される
  - 著者が批判を受けて投稿を編集
  - 編集内容が批判内容と関連している（LLM判定）
- **記録内容**:
  - OutputHistoryテーブルに`contributor_ids`配列追加
  - 批判者のuser_idを記録
  - UI上で「この改善に貢献した批判」として表示
- **優先度**: P1（Phase 2）

### FR-LH-021: 批判品質スコア
- **定義**: 批判の論理性・建設性をLLMで評価
- **実装**: 批判引用時に品質スコア（0-100）を自動計算
- **優先度**: P2（Phase 2）

## 5. インセンティブ・エコシステム

### 5.1 称号・キャッチコピーシステム

#### FR-LH-030: LLMによる二つ名授与
- **定義**: 実績に応じてLLMが「論理の外科医」「未踏地の観測者」等の二つ名を授与
- **授与条件**:
  - 一定数以上の被引用
  - 特定分野での継続的貢献
  - 高い乖離度+密度の投稿
- **重要原則**: **称号は審査のショートカット権限を与えない**
- **実装**:
  - 月次バッチでLLMが全ユーザーの投稿傾向を分析
  - 3-5語の二つ名を生成
  - User.titleフィールドに保存
- **優先度**: P2（Phase 3）

### 5.2 引用による権威

#### FR-LH-031: PageRankベースのレコメンド
- **実装済み**: task-breakdown.md T-240参照
- **追加要件**: 「いいね」を一切表示しない（被引用数のみ）

## 6. フィードバック・コーチング

### FR-LH-040: 不採用時のメンター機能
- **定義**: Private判定時に「なぜ届かなかったか」をLLMが論理的に解説
- **フィードバック内容**:
  1. **乖離度不足**: 「既存の投稿[OUT-XXX]と類似しています」
  2. **密度不足**: 「抽象的な表現が多く、具体例が不足しています。例えば...」
  3. **再挑戦の問い**: 「この視点をさらに深めるなら、次のような問いを考えてみてください」
- **実装**:
  - AI査読後、LLMにフィードバック生成プロンプトを実行
  - 結果をユーザーに通知
- **優先度**: P0（Phase 2）

### FR-LH-041: 知のジム化
- **定義**: 投稿を通じてユーザーの論理的思考と文章解像度を強制的に引き上げる
- **実装**:
  - 投稿回数とフィードバック受諾率の記録
  - ユーザーダッシュボードで「論理強化スコア」を可視化
- **優先度**: P2（Phase 3）

## 7. 公平性の美学（Anti-Authority Bias）

### FR-LH-050: ジャイアント・キリング記録
- **定義**: 無名な新人の「狂気」が既存の「権威」の矛盾を突いた場合、歴史的転換点として記録
- **検出ロジック**:
  1. フォロワー数100未満のユーザーが投稿
  2. フォロワー数10,000以上のユーザーの投稿を`criticize`引用
  3. 批判が広く支持される（被引用数・同意見数）
  4. システムが自動検出し「Giant Killing」バッジを付与
- **実装**:
  - 週次バッチでパターン検出
  - 特別な履歴イベントとして記録
  - ホームページの「歴史的転換点」セクションに掲載
- **優先度**: P2（Phase 3）

### FR-LH-051: 権威性メトリクスの排除
- **要件**: UI上でフォロワー数を過度に強調しない
- **実装**:
  - プロフィール詳細ページにのみ表示
  - フィード・検索結果では非表示
- **優先度**: P1（Phase 1）

## 8. 永続化プロトコル

### FR-LH-060: 削除不可の同意プロセス
- **要件**: 投稿時、ユーザーは以下に明示的に同意
  - 「パブリック化（ハッシュチェーン連結）された情報の削除不可」
  - 「個人の所有物から人類の共有資産へ移行」
- **実装**:
  - 初回投稿時に同意モーダル表示
  - `user.has_agreed_to_protocol`フラグで管理
- **優先度**: P0（Phase 1）

### FR-LH-061: 知の共有資産化
- **定義**: Public Outputは著者の所有物ではなく、人類の共有財産
- **法的整理**:
  - CC BY-SA 4.0ライセンスの自動適用
  - 退会後も投稿は永久保存
  - ただしGDPR対応として匿名化オプション提供
- **優先度**: P0（Phase 1）

## 9. データモデル追加

### 9.1 Userテーブル追加フィールド
```sql
ALTER TABLE users ADD COLUMN title VARCHAR(100);  -- LLM生成の二つ名
ALTER TABLE users ADD COLUMN has_agreed_to_protocol BOOLEAN DEFAULT FALSE;
ALTER TABLE users ADD COLUMN logic_enhancement_score FLOAT DEFAULT 0;
```

### 9.2 OutputHistoryテーブル追加フィールド
```sql
ALTER TABLE output_history ADD COLUMN contributor_ids UUID[];  -- 批判による貢献者
```

### 9.3 新規テーブル: GiantKillingEvent
```sql
CREATE TABLE giant_killing_events (
    id UUID PRIMARY KEY,
    challenger_output_id VARCHAR(30) REFERENCES outputs(id),
    target_output_id VARCHAR(30) REFERENCES outputs(id),
    challenger_user_id UUID REFERENCES users(id),
    target_user_id UUID REFERENCES users(id),
    support_count INT DEFAULT 0,  -- 被引用数+同意見数
    detected_at TIMESTAMP NOT NULL,
    created_at TIMESTAMP DEFAULT NOW()
);
```

### 9.4 新規テーブル: AIReviewFeedback
```sql
CREATE TABLE ai_review_feedback (
    id UUID PRIMARY KEY,
    output_id VARCHAR(30) REFERENCES outputs(id),
    divergence_score FLOAT,  -- 乖離度
    density_score FLOAT,  -- 内部密度
    reverse_simulation_score FLOAT,  -- 逆シミュレーション
    feedback_text TEXT,  -- メンター的フィードバック
    improvement_suggestions TEXT[],  -- 改善提案
    created_at TIMESTAMP DEFAULT NOW()
);
```

## 13. 倫理・法的考慮

### GDPR対応
- 削除不可だが「匿名化」は可能
- 著者情報のみ削除、コンテンツは保持

### AI倫理
- LLMバイアスの定期監査
- フィードバックの公平性検証

### 知的財産権
- CC BY-SA 4.0ライセンスの明示
- 退会時の権利移譲に関する同意
